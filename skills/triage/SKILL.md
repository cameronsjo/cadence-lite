# Triage

Turn saved possibilities into a small set of useful decisions. The failure this
prevents: a backlog that keeps growing while stale premises and duplicated work
keep getting promoted.

## Approach

- **Bound the review.** Use the supplied list or named backlog and the user's
  priorities. Do not sweep unrelated projects. If the source or a consequential
  priority is missing, ask for it rather than inventing one.
- **Recheck what matters.** Verify whether candidate work is still needed, already
  done, duplicated, or dependent on an unresolved decision. Existing issue text is
  a claim, not current evidence. Mark unavailable evidence as uncertain rather
  than treating it as a reason to discard an item.
- **Recommend a disposition.** Weigh benefit, effort, risk, and dependencies against
  the user's priorities. Offer an ordered shortlist to act on, with brief reasons;
  identify what to defer or drop. Preserve distinct requirements when grouping
  duplicates. Avoid invented scores and precision the evidence cannot support.
- **Separate decisions from actions.** Present recommendations by default. Change
  records only within the user's authorization, preserving enough rationale to
  understand the disposition later. A recommendation to act is not permission to
  implement, close issues, or delete captures.

Keep the result proportional to the input. Name any decision the user must make
before the next task is actionable; a full implementation plan belongs after the
task is selected.
